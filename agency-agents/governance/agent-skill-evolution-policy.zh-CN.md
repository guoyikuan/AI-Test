# Agent / Skill 受控自动演进政策

- 版本：`v1`
- 状态：`adopted`
- 作用域：当前 AI-Test 仓库内可复用的 Skill、Agent、编排、协议、脚本、评测与治理机制
- 非目标：普通业务开发、日常运维、生产操作及与 Agent / Skill 工程无关的功能变更

## 1. 范围限定

只演进可复用的 Skill、Agent、协议、脚本、评测和治理机制。不得把普通业务开发、日常运维或一次性任务包装成“自我进化”。

## 2. 先证据，后改变

演进证据只能来自真实使用、失败评测、用户纠正、重复能力、工具拒绝或性能问题，并且必须脱敏、可验证、可追溯。没有可验证证据时，只能记录观察，不得产生有效改动或生命周期晋升。

## 3. 生命周期受控

能力使用以下生命周期：

`observed -> candidate -> validated -> adopted -> deprecated -> retired`

不合格能力进入 `rejected`。每次状态迁移必须记录迁移原因、证据引用、责任主体、时间和回滚路径；不得跳过适用的验证与治理门禁。

## 4. 去重与单一事实源

新增或调整能力前，必须盘点当前仓库及适用的全局 Skill / Agent。相同或高度重叠的能力优先合并或扩展，不创建重复实现。每个活跃 Skill 必须只有一个明确的 canonical source；适配器只能引用或转换该来源，不得形成第二套治理逻辑。

## 5. 权限不可因演进扩大

演进不得自动增加工具权限、仓库写权限、生产权限或发布权限。当前测试仓库之外保持只读；任何高风险写入、提交、推送、合并、发布、外部副作用或生产动作，仍需当前用户明确授权并通过既有门禁。

## 6. 评测与对抗复核

每个候选能力必须绑定：

- 冻结输入及其摘要或哈希；
- 明确的评分规则和通过阈值；
- 可审计的运行回执与证据引用；
- 超时、拒绝、失败和回滚行为。

高风险决策必须由独立验证方复核，生产者不得依靠自评批准自身结果。

## 7. 完成门禁

任何“完成”“通过”“已修复”或“可发布”的结论，都必须获得新鲜、绑定当前任务范围和证据的 `supervisor.assurance-decision/v1`，且 `decision=ALLOW`。缺少证据、验证超时、范围漂移、测试跳过、证据失配或 Supervisor 非 `ALLOW` 时，一律视为阻断。

## 8. 可回滚与可审计

每项采用必须保留来源、变更摘要、证据、生命周期事件和回滚引用。不得静默覆盖历史，不得删除失败记录、拒绝原因或其他不利证据。弃用和退役必须保留恢复方式及替代能力说明。

## 9. 记忆受用户控制

Agent 不得自行写入长期记忆。只有当前用户明确要求时，才可以通过独立、可审计、可回滚的记录更新记忆；演进观察、候选提议或采用结果本身不构成记忆写入授权。

## 最小演进记录

每次演进至少记录以下字段：

- `capability_id`
- `canonical_source`
- `lifecycle_state`
- `scope`
- `evidence_refs`
- `evaluation_contract`
- `permission_ceiling`
- `decision`
- `decision_reason`
- `rollback_ref`
- `updated_at`

本政策只建立仓库内治理契约，不自动授权代码修改、测试执行、提交、推送、合并、发布、生产操作或长期记忆写入。
