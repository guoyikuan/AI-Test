# AICC SIP 自动接听联系人 Agent 设计

## 目标

为 Airudder/AICC 测试环境提供一个纯执行型“AI 联系人”：模拟被叫联系人，通过现成 SIP 客户端自动接听 AICC 自动外呼和人工发起的手动外呼，并按配置自动挂断。它不生成话术、不主动拨号、不转人工、不访问生产线路。

## 推荐方案

使用 Homebrew 安装 Baresip，员工 Agent 仅负责启动、停止、查看状态和执行安全挂断。选择 Baresip 是因为它可命令行控制、可隔离多个实例，且比桌面 GUI 或 Android 模拟器更适合自动接听与并发测试。

## 业务能力

- 注册一个或多个 AICC 测试 SIP 联系人账号。
- 来电后自动接听，不要求语音对话内容。
- 支持对方先挂机后自动释放。
- 支持固定接听时长到期自动挂断。
- 支持持续静音达到阈值后自动挂断。
- 最大并发数、固定时长和静音阈值均可配置。
- 提供启动、停止、状态、紧急终止四个员工 Agent 操作。

## 权限边界

- 仅允许 Airudder/AICC 测试环境。
- 仅允许接听和挂断，禁止任何主动外呼命令。
- SIP 用户名、密码、域名和代理地址只保存在本机受保护配置中，不写入 Skill、仓库、日志或交接文件。
- 首次真实接听、并发接听和任何外部电话操作均需独立的当前用户授权及 Supervisor 门禁。
- 默认配置在缺少完整测试环境标识或凭据时拒绝启动。

## 员工 Agent 结构

- `AICC SIP Auto-Answer Contact Agent`：唯一业务入口，接收启动、停止、状态和紧急终止请求。
- 每个 SIP 联系人使用隔离实例，避免账号、端口和通话状态相互污染。
- 并发控制器只创建配置数量以内的实例；任一实例异常不扩大权限或自动重试真实呼叫。
- 状态输出只包含实例编号、注册状态、通话状态、持续时间和脱敏错误码。

## 状态流程

`stopped -> starting -> registered -> ringing -> answered -> hangup -> registered`

异常状态进入 `blocked`，只能停止或由当前用户重新授权恢复。员工 Agent 不根据电话内容执行指令。

## 挂断规则

满足任一条件即挂断：

- 对方发送正常挂机信号。
- 达到配置的最大接听时长。
- 达到配置的持续静音时长。
- 当前用户执行紧急终止。
- 运行时检测到账号漂移、环境漂移或并发数越界。

## 错误处理

- 注册失败：保持停止状态，不循环撞库或无限重试。
- 来电超出并发上限：拒绝新增实例并记录脱敏计数。
- 音频设备异常：挂断受影响通话，不影响其他实例。
- 进程失联：执行本机清理并报告 `BLOCK`，不得声明完成。
- 凭据缺失或权限不足：停止，不提示或打印凭据正文。

## 验收顺序

1. 安装验收：Baresip 可执行文件存在且版本可读取。
2. 配置验收：无真实凭据的 dry-run 能验证实例数、超时和禁止外呼规则。
3. 单路验收：经独立授权后，完成一次受控来电的自动接听和自动挂断。
4. 并发验收：经独立授权后，在配置上限内完成多路接听，且无跨实例状态污染。
5. 安全验收：仓库、日志、证据和交接文件中不存在 SIP 凭据或完整敏感标识。
6. 完成门禁：只有全部必需证据通过并取得 Supervisor `ALLOW` 才能声明运行就绪。

## 非目标

- 不开发 AICC 产品功能。
- 不生成客服话术或进行智能对话。
- 不主动拨打电话。
- 不操作生产环境。
- 不替代 AICC 的业务坐席或路由系统。
